# 标准工作流程（一）：fmt、init、validate

从代码到资源之前，先了解 OpenTofu 工作流的前三步。

```mermaid
flowchart LR
    A[编写代码] --> B[tofu fmt]
    B --> C[tofu init]
    C --> D[tofu validate]
    D --> E[tofu plan]
```

## 核心要点

* tofu fmt 用于格式化代码，常配合 -recursive 处理所有子目录
* tofu init 会下载 Provider、下载 Module、初始化 Backend，并生成或更新 .terraform.lock.hcl
* .terraform.lock.hcl 用于锁定 Provider 具体版本和校验信息，应当提交到 Git
* tofu validate 能发现属性名称错误、类型错误、引用不存在等问题，但不能保证权限或镜像一定存在

---

## 本章测验

本章共 5 道单项选择题。

### 第 1 题

tofu init 命令的主要作用不包括下列哪一项？

- A. 下载 Provider
- B. 初始化 Backend
- C. 创建或更新 .terraform.lock.hcl
- D. 直接在 OCI 中创建资源

<details>
<summary>选择答案后查看结果</summary>

正确答案：D

答案解析：tofu init 负责下载 Provider、下载 Module、初始化 Backend 并生成 lock 文件，真正创建资源是 tofu apply 的工作。

</details>

### 第 2 题

.terraform.lock.hcl 文件的作用是什么？

- A. 锁定 Provider 的具体版本和校验信息
- B. 保存 OCI 认证密钥
- C. 保存 State 数据
- D. 记录用户的点击历史

<details>
<summary>选择答案后查看结果</summary>

正确答案：A

答案解析：文中说明该文件用于锁定 Provider 的具体版本和校验信息，并且应当提交到 Git 以保证团队使用一致的 Provider 版本。

</details>

### 第 3 题

tofu validate 能够发现下列哪种问题？

- A. OCI 权限是否足够
- B. 属性名称是否写错
- C. 指定镜像是否真实存在
- D. 创建的资源是否会产生额外费用

<details>
<summary>选择答案后查看结果</summary>

正确答案：B

答案解析：文中明确指出 tofu validate 能发现属性名称错误、参数类型错误、引用不存在、Provider 配置不完整等问题，但不能保证权限、镜像存在性或费用。

</details>

### 第 4 题

以下哪个命令用于格式化整个项目目录下的所有代码？

- A. tofu validate -all
- B. tofu init -format
- C. tofu fmt -recursive
- D. tofu plan -fmt

<details>
<summary>选择答案后查看结果</summary>

正确答案：C

答案解析：tofu fmt -recursive 会递归格式化项目中的所有配置文件。

</details>

### 第 5 题

团队协作时，为什么建议将 .terraform.lock.hcl 提交到 Git？

- A. 因为它包含 State 数据，必须备份
- B. 因为它是必须加密的敏感文件
- C. 因为不提交会导致 tofu fmt 报错
- D. 因为它能保证团队成员使用相同的 Provider 版本

<details>
<summary>选择答案后查看结果</summary>

正确答案：D

答案解析：lock 文件锁定了 Provider 的具体版本和校验信息，提交到 Git 可以确保团队所有成员及 CI 环境使用一致的 Provider 版本，避免因版本差异导致的问题。

</details>
