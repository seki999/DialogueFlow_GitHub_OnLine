# SNMP Trap接收设计

设备故障或状态变化时会主动发送Trap，接收端需要能应对突发流量。

```mermaid
flowchart LR
    DEV[设备] -->|UDP 162| RECV[Trap Receiver]
    RECV --> PARSE[快速解析基本字段]
    PARSE --> QUEUE[内部队列]
    QUEUE --> NORM[异步标准化]
    NORM --> DB[(数据库)]
```

## 核心要点

* Trap通常通过UDP 162端口发送，可能丢失、乱序或重复
* 需要解析来源IP、SNMP版本、Trap OID、Variable Binding等字段
* 推荐流程：快速接收解析后放入队列，异步处理，避免阻塞接收
* SNMP Trap属于入站流量，应使用OCI NLB接收

---

## 本章测验

本章共 5 道单项选择题。

### 第 1 题

SNMP Trap的典型接收端口是什么？

- A. UDP 161
- B. TCP 514
- C. TCP 443
- D. UDP 162

<details>
<summary>选择答案后查看结果</summary>

正确答案：D

答案解析：SNMP Trap通常发送到UDP 162端口，而SNMP GET/GETNEXT等操作通常使用UDP 161端口。

</details>

### 第 2 题

为什么不建议Trap Receiver在收到报文后立即同步执行大量数据库操作？

- A. UDP可能突发大量报文，同步处理容易造成阻塞或丢包
- B. 数据库不支持写入Trap数据
- C. 同步操作在Java中无法实现
- D. 这样做会导致Trap格式错误

<details>
<summary>选择答案后查看结果</summary>

正确答案：A

答案解析：Trap可能在故障时突然大量涌入，如果同步执行复杂的数据库操作，容易造成处理跟不上、进而丢失后续报文。

</details>

### 第 3 题

推荐的Trap处理流程是怎样的？

- A. 直接丢弃所有报文
- B. 先快速解析基本字段放入内部队列，再异步标准化写入数据库
- C. 把所有Trap原样转发给用户浏览器
- D. 只在数据库满了以后才处理

<details>
<summary>选择答案后查看结果</summary>

正确答案：B

答案解析：推荐先做轻量的解析并放入队列以尽快继续接收，然后再异步进行标准化和持久化处理。

</details>

### 第 4 题

SNMP Trap在网络架构上应该通过什么方式对外暴露入口？

- A. OCI Load Balancer（HTTP）
- B. 不需要任何入口，直接连Pod IP
- C. OCI Network Load Balancer
- D. 通过OCIR镜像仓库

<details>
<summary>选择答案后查看结果</summary>

正确答案：C

答案解析：Trap是UDP协议的入站流量，应使用支持TCP/UDP的OCI NLB来接收，而不是HTTP负载均衡器。

</details>

### 第 5 题

以下哪项不属于Trap Receiver通常需要处理的问题？

- A. 报文丢失
- B. 报文乱序或重复
- C. 设备时钟不准确
- D. Spring MVC的Controller注解冲突

<details>
<summary>选择答案后查看结果</summary>

正确答案：D

答案解析：Controller注解冲突属于Web开发问题，与UDP Trap接收场景中常见的丢失、乱序、重复、时钟不准等问题无关。

</details>
