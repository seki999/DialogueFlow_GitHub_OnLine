# OpenTofu + OCI + OKE 网络设备监控平台 — 教学课程

## 课程主题

本课程围绕一套基于 **OpenTofu、OCI、OKE Kubernetes、Spring Boot 和 Oracle Database** 构建的网络设备监控平台展开，覆盖 IaC 基础设施、OCI 网络、容器编排、TCP Ping / SNMP GET / SNMP Trap / Syslog 四种通信方式、负载均衡选型、数据库设计、密钥管理、高可用与自监控体系等内容。

## 总章节数

共 **30** 章（长课程规格）。

## 文件说明

每个章节由一对同名文件组成：

```
编号.md            # 图文教学内容 + 本章 5 道单项选择题
编号.conversation   # 双人讲解对话（speaker 1 / speaker 2）
```

编号从 `01` 到 `30`，连续不跳号。`.md` 与 `.conversation` 内容严格对应，讲解同一主题。

## 推荐播放顺序

按编号从 01 到 30 顺序播放/阅读，章节之间具有自然的学习递进关系（背景 → 核心概念 → 架构 → 协议实现 → 负载均衡 → 数据库 → 运维 → 总结）。

## 选择题说明

* 每章末尾固定包含 **5 道单项选择题**，每题 4 个选项（A/B/C/D），只有一个正确答案。
* 题目覆盖本章讲解过的知识点，不涉及尚未讲解的内容。
* 正确答案位置已在全课程范围内做了均衡分布，不会集中在同一个字母。

### 数据块读取方式

每个 `.md` 文件末尾都包含一段 HTML 注释包裹的机器可读数据块：

```
<!-- QUIZ_DATA_START
{
  "chapter": "01",
  "questions": [ { "id": 1, "question": "...", "options": {...}, "answer": "B", "explanation": "..." } ]
}
QUIZ_DATA_END -->
```

课程播放器或自定义脚本可以用正则提取 `QUIZ_DATA_START` 与 `QUIZ_DATA_END` 之间的内容，再用 `json.loads()`（Python）或 `JSON.parse()`（JavaScript）解析，得到结构化的题目、选项、正确答案和解析。

## GitHub 静态查看方式

在 GitHub 等普通 Markdown 渲染环境中，每道题的正确答案和解析被包裹在 `<details><summary>` 折叠区域中，读者点击展开即可查看。

**注意**：普通 GitHub Markdown 只能通过折叠区域手动查看答案，不能自动判定用户点击了哪个选项。如需实现"点击选项后自动判断正误并显示答案"的完整互动效果，需要由课程播放器读取上述 `QUIZ_DATA` 数据块并自行实现交互逻辑（渲染选项按钮、监听点击、比对答案、展示结果）。

## 课程播放器互动答题方式

推荐的播放器交互流程：

1. 显示题目和 A/B/C/D 四个选项
2. 等待用户点击一个选项，随后锁定本题
3. 判断该选项是否等于 `QUIZ_DATA` 中的 `answer`
4. 显示"回答正确/回答错误"，标出用户选择和正确选项，展示 `explanation`
5. 在用户点击前，不得提前显示任何答案或通过样式提示

## 得分规则

每章满分 5 分，每题 1 分。完成本章 5 题后：

```
本章得分：X / 5
正确率：X/5 * 100%
```

反馈建议：

* 5 分：本章知识掌握得很好
* 4 分：整体掌握良好，可复习答错的知识点
* 3 分：已理解主要内容，建议重新查看本章重点
* 0～2 分：建议重新学习本章后再次答题

## 内容依据

本课程内容基于用户提供的技术文章整理而成，重新组织为教学逻辑顺序（背景 → 核心概念 → 架构 → 实现细节 → 运维），未添加原文中没有依据的事实性内容。
