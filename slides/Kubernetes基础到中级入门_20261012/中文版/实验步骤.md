# 动手实验：副本、稳定入口和持久化

## 准备与范围

需要已有学习集群、kubectl、镜像拉取能力；存储实验另需匹配 PV 或可用默认 StorageClass。本课程不安装集群。下面从本课“中文版”目录执行。使用独立 k8s-learn Namespace；若已存在同名资源，请先确认属于自己的实验。

```bash
kubectl config current-context
kubectl cluster-info
kubectl get nodes
kubectl create namespace k8s-learn
```

检查点：当前上下文是学习集群，节点能提供运行条件。若命名空间已由前面章节创建，不必再次 create。

## 1. 部署 Web 和 Service

```bash
kubectl apply -f examples/02-deployment.yaml
kubectl apply -f examples/03-service.yaml
kubectl rollout status deployment/web -n k8s-learn
kubectl get deployment,rs,pods,service -n k8s-learn
kubectl get endpointslices -n k8s-learn -l kubernetes.io/service-name=web-service
```

检查点：Deployment 的可用副本达到目标 3，Pod 标签 app=web，EndpointSlice 包含后端信息。readinessProbe 检查 Nginx 根路径，不能替代真实业务测试。

## 2. 本地访问与扩容

```bash
kubectl port-forward service/web-service 8080:80 -n k8s-learn
```

保持该终端运行，在本机浏览器访问 http://localhost:8080，预期看到 Nginx 默认页面。port-forward 是临时本地通道，不创建公网入口，也不证明所有 Service 转发路径均已测试。扩容在另一个终端执行：

```bash
kubectl scale deployment web --replicas=5 -n k8s-learn
kubectl rollout status deployment/web -n k8s-learn
kubectl get pods -n k8s-learn -l app=web
```

检查点：目标副本变为 5，随后观察是否全部就绪。把 examples/02-deployment.yaml 中 replicas 同步改为 5，避免下次 apply 恢复到 3；不要只记录临时命令。

## 3. 观察受管 Pod 的替代

先记录一个实际 Web Pod 的名称。把下面 WEB_POD_NAME 占位符换成自己的名称，不能原样执行。

```bash
kubectl get pods -n k8s-learn -l app=web -o wide
kubectl delete pod WEB_POD_NAME -n k8s-learn
kubectl get pods -n k8s-learn -l app=web -w
```

检查点：旧对象终止，控制器创建替代对象，数量逐步恢复到 5；名称、IP、节点可能变化。Ctrl+C 结束观察。若 port-forward 所连的 Pod 被删除，本地通道可能结束，需要重新运行它；不能把通道中断直接判成 Service 入口失效。

## 4. 申请持久卷并创建消费者

```bash
kubectl get storageclass
kubectl apply -f examples/04-pvc.yaml
kubectl apply -f examples/05-data-writer.yaml
kubectl get pvc -n k8s-learn
kubectl get pod data-writer -n k8s-learn
kubectl wait --for=condition=Ready pod/data-writer -n k8s-learn --timeout=120s
```

检查点：PVC 最终 Bound，消费者就绪。有些类使用 WaitForFirstConsumer，需要消费者参与调度后才完成绑定；若条件不足或超时，应先核对实际存储供给与 Pod 状态，本课不伪造成功输出。

## 5. 写标记，只重建消费者

```bash
kubectl exec data-writer -n k8s-learn -- sh -c "echo k8s-learning-marker > /data/marker.txt"
kubectl exec data-writer -n k8s-learn -- cat /data/marker.txt
kubectl delete pod data-writer -n k8s-learn
kubectl apply -f examples/05-data-writer.yaml
kubectl wait --for=condition=Ready pod/data-writer -n k8s-learn --timeout=120s
kubectl exec data-writer -n k8s-learn -- cat /data/marker.txt
```

检查点：重新创建后仍输出 k8s-learning-marker。整个过程保留 data-pvc；它证明这个存储配置下的数据保留，不证明存储永不丢失，更不等于数据库备份。

## 6. 可选更新练习

```bash
kubectl set image deployment/web web=nginx:1.28 -n k8s-learn
kubectl rollout status deployment/web -n k8s-learn
kubectl get rs,pods -n k8s-learn
```

观察新 ReplicaSet 和逐步替换；同步更新 Deployment 文件中的镜像。教学标签不是最新版建议。

## 7. 清理边界

停止 port-forward。若仅做了本页主线实验，可先删除自己的无状态资源与存储消费者，保留 PVC：

```bash
kubectl delete -f examples/02-deployment.yaml
kubectl delete -f examples/03-service.yaml
kubectl delete -f examples/05-data-writer.yaml
```

其他章节的可选对象需按自己实际创建的清单清理。删除 Namespace 会连同其中的 PVC 删除，可能依据 PV 回收策略删除底层卷。只有确定不需要实验数据且该 Namespace 仅包含自己的实验对象时，才选择执行以下完整清理：

```bash
kubectl delete namespace k8s-learn
```

本课程制作时未连接集群执行以上命令。请记录每一步实际现象，而不是把示例文字当作运行日志。
