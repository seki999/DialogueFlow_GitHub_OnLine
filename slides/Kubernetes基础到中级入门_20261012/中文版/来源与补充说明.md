# 来源与补充说明

## 主要输入

用户粘贴的《Kubernetes（K8s）基础教程：从零理解架构、组件、作用场景与相互关系》，以及仓库根目录的“提示词_从技术内容生成md和对话.txt”。原文包括章节目录、第一至第十二章正文及第十三章部分正文，未保留完整代码块。

本课重新组织为 27 个主题，未机械按原段落切分。第 24 章的 Helm 完整讲解、第 25 章架构串联、第 26 章实验和第 27 章总结是依据已有概念设计的补充；第 24 章之后均明确说明原文边界。第 14 章不把原文 nginx 类名作为所有集群的安装前提，改为要求选择实际可用类。

## 官方补充核对依据

- [Kubernetes 组件](https://kubernetes.io/docs/concepts/overview/components/)：核对组件职责和可替代的 Service 转发实现。
- [Pod](https://kubernetes.io/docs/concepts/workloads/pods/)：核对 Pod 与容器的共同运行关系。
- [Deployment](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/)：补充完整资源结构、发布流程和查询命令。
- [就绪探针](https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/)：核对实验中 HTTP readinessProbe 的作用。
- [Service](https://kubernetes.io/docs/concepts/services-networking/service/)：核对 selector、端口、类型及后端关系。
- [DNS](https://kubernetes.io/docs/concepts/services-networking/dns-pod-service/)：核对跨 Namespace 服务名与可配置集群域名。
- [Ingress](https://kubernetes.io/docs/concepts/services-networking/ingress/)：补充 networking.k8s.io/v1 示例，说明规则与 Controller 的区别、Ingress API 冻结及 Gateway API 后续方向。
- [ConfigMap](https://kubernetes.io/docs/concepts/configuration/configmap/)：补充精确键引用以及环境变量、文件挂载和 subPath 的更新边界。
- [Secret](https://kubernetes.io/docs/concepts/configuration/secret/)：补充 stringData 和 secretKeyRef 示例。
- [PV 与 PVC](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)：补充存储声明、消费者与回收边界。
- [StorageClass](https://kubernetes.io/docs/concepts/storage/storage-classes/)：核对默认类与 WaitForFirstConsumer 的供给前提。
- [StatefulSet](https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/)：补充两个副本的教学结构和 PVC 命名。
- [CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/)：补充 Asia/Tokyo 时区、Forbid 并发限制和执行边界。
- [Helm Chart](https://helm.sh/docs/topics/charts/)：补充 Chart、values、release 的对应关系，使用占位本地 Chart 路径。

## 示例性质

全部完整 YAML 为新编写的最小教学示例；片段明确注明嵌入位置。配置与密码示例不连接真实数据库；DaemonSet 不采集真实日志；StatefulSet 不建立数据库复制；Job 与 CronJob 仅输出文本。第 26 章用文件标记验证数据是否跨消费者 Pod 重建保留，不能由此认定数据库备份已完成。

文档核对日期：2026-10-12。实际环境请以自己的 Kubernetes API 支持能力和已安装组件为准。
