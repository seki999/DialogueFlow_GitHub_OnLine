# 26 动手实验：副本、访问与持久化

在独立 Namespace 中观察实际变化，并用检查点确认结果。

```mermaid
flowchart LR
 A[准备学习集群] --> B[部署 Web 与 Service]
 B --> C[访问并扩容]
 C --> D[删除一个受管 Pod]
 D --> E[观察替代与入口]
 E --> F[写入 PVC 文件]
 F --> G[只重建消费者 Pod]
 G --> H[确认文件仍存在]
```

## 核心要点

- **1. 这个实验有哪些前提？** 已有可访问的学习集群和 kubectl，能够拉取示例镜像，并有合适 PV 或默认 StorageClass。实验只操作 k8s-learn，存储部分条件不足时不假设一定能完成。
- **2. 为什么先做 Web 和 Service？** 先验证无状态运行与稳定访问：三个 Web 副本通过 Service 提供入口，再用本地 port-forward 访问。扩容后要同步观察数量，地址入口不需要记住每个 Pod IP。
- **3. 删除一个受管 Pod 应该观察什么？** 记录原 Pod 名称，再只删除这个 Deployment 管理的实例，观察替代 Pod 和副本恢复。它与之前删除独立 Pod 的结果不同。
- **4. 持久化部分怎样证明数据保留？** 向 /data 写入一个标记文件，只删除 data-writer Pod，保留 PVC，再重新创建同一消费者并读取文件。成功的检查点是原标记仍可读取，不是仅看到 Pod 为 Running。
- **5. 实验里也部署数据库吗？** 不部署真实数据库。它用 nginx 和 busybox 分别验证运行、访问及存储关系，避免把文件保留实验说成数据库复制或备份测试。清理时要单独决定是否删除 PVC。

## 场景与示例

**按实验步骤记录结果**

实验说明包含命令、应观察的现象和清理边界。port-forward 终端需要保持运行，删除消费者前确认其名称，清理 Namespace 会包含其中的 PVC，可能触发底层卷删除。

实验完整步骤见 [实验步骤.md](实验步骤.md)。可直接应用的文件位于 examples/；主线只使用 Namespace、Deployment、Service、PVC 和消费者 Pod。

## 常见误区

**Pod 重建成功就能证明持久化正确**

还需要读取原标记文件；Pod 启动与数据保留是不同验证目标。

### 第 2 题

先记录 Pod 名称再删除受管实例，是为了观察什么？

- A. 替代实例与副本恢复
- B. 镜像自动升级到最新版
- C. Namespace 自动复制
- D. Secret 自动轮换

<details>
<summary>选择完成后展开答案</summary>

正确答案：A

答案解析：删除受管实例观察控制器创建替代 Pod 并恢复目标副本。

</details>

### 第 3 题

port-forward 的实验访问特点是什么？

- A. 自动创建永久公网域名
- B. 自动安装 Ingress Controller
- C. 自动生成云负载均衡器
- D. 终端保持运行时提供本地入口

<details>
<summary>选择完成后展开答案</summary>

正确答案：D

答案解析：port-forward 是临时本地入口，不创建永久公网基础设施。

</details>

### 第 4 题

验证 PVC 数据保留时，应删除什么？

- A. 先删除 PVC 再重建 Pod
- B. 只删除消费者 Pod 并保留 PVC
- C. 先删除整个 Namespace
- D. 先清空真实磁盘再查询 Service

<details>
<summary>选择完成后展开答案</summary>

正确答案：B

答案解析：只删消费者、保留 PVC，才是在验证同一存储跨 Pod 重建保留。

</details>

### 第 5 题

哪个结果直接支持原数据保留？

- A. 重建后读到原标记文件
- B. 新 Pod 显示 Running
- C. Service 有 ClusterIP
- D. Deployment 名称没有改变

<details>
<summary>选择完成后展开答案</summary>

正确答案：A

答案解析：重新读到原标记是数据保留证据；Running 和 ClusterIP 不能证明。

</details>
