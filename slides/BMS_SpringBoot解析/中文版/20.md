# 20 JPA、事务边界与 Flyway

理解实体持久化、延迟加载、模式校验和数据库迁移的职责分工。

```mermaid
flowchart LR
    A["Service 事务"] --> B["Repository"]
    B["Repository"] --> C["EntityGraph 或 LAZY"]
    C["EntityGraph 或 LAZY"] --> D["Hibernate validate"]
    D["Hibernate validate"] --> E["Flyway migration"]
    E["Flyway migration"] --> F["数据库"]
```

## 核心要点

- Spring Data JPA Repository 提供持久化访问，关联通常使用 LAZY。
- 需要列表关联时可用 EntityGraph 明确加载，减少 N+1 查询。
- open-in-view=false 禁止模板渲染阶段依赖仍打开的数据库 Session。
- ddl-auto=validate 只校验 Entity 与表结构，不自动修改数据库。
- 真正的结构变更由 Flyway 迁移负责。

## 实现边界

- 关闭 open-in-view 后，页面所需数据必须在 Service 事务内准备。
- validate 通过不等于迁移脚本已经在所有环境执行。
