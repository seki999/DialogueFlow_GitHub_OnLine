## 核对与补充的重点

OCI Provider 的 APIKey profile 用于本机已配置的认证资料，不使用不存在的 ConfigFile 认证方式。客户端示例明确 Context 与路径，私有 Endpoint 仍需实际网络通道。Registry 页面主要由前端加载，本次同时读取官方 Provider 仓库中的资源文档核对字段。

LB/NLB Annotation 使用 oci.oraclecloud.com/load-balancer-type，值 lb 与 nlb；入口是否公网另由配置决定。后端 Node/Pod 路径随 CNI 和实现变化，不画成所有集群通用的固定链路。OCIR 仓库 namespace 与 Kubernetes Namespace 不同，拉取凭据与网络都须具备。

存储示例以 Managed Nodes 和实际可用的 OCI Block Volume CSI 类为条件。oci-bv 不是所有环境必有的名称；Bound 不等于挂载和数据库读写成功。Terraform 独立卷与 CSI 动态卷不因为同容量就自动成为同一资源。

Nginx 工程仅将非敏感网页放入 ConfigMap，两个副本、Service 与读取配置的关系可自行验证，不部署真实数据库。其他示例不包含真实认证信息；定时任务仅输出文本，Ingress 与 OCIR 地址都是需替换的条件性值。
