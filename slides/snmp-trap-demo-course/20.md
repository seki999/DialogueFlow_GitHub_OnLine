# 20. Docker Compose本地部署实战

了解了各组件原理之后，这一章走一遍从零启动整套系统、发送测试通知、验证结果的完整流程。

```mermaid
flowchart LR
  S1[生成Secret文件] --> S2[docker compose up -d --build]
  S2 --> S3[等待healthcheck全部通过]
  S3 --> S4[iot-simulator发送测试通知]
  S4 --> S5[Web页面查看结果]
  S5 --> S6[docker compose down 停止]
```

## 核心要点

* 启动前必须先执行generate-secrets脚本，生成oracle密码、API Token、SNMPv3口令等Secret文件到runtime-secrets目录
* docker compose up -d --build会按依赖顺序启动oracle-db、两个monitoring-app、两个trap-receiver和gateway，健康检查未通过前依赖它的服务不会启动
* iot-simulator是一个带profiles: [tools]的服务，平时不会随docker compose up启动，需要用--profile tools run单独调用
* 验证成功的标准是SNMP RESPONSE且errorStatus=noError，而不是简单的UDP写入成功，这与第4章讲过的Inform确认机制一致
* docker compose down -v会删除所有数据卷，包括Oracle数据、USM状态和未处理完的重试队列，生产数据或故障排查场景要避免误用

## 本章测验

本章共 5 道单项选择题。

### 第 1 题

启动docker compose服务之前，第一步应该做什么？

- A. 先手动创建Oracle数据库表
- B. 先编译Java源代码
- C. 直接运行docker compose up
- D. 先执行generate-secrets脚本，生成必要的Secret文件到runtime-secrets目录

<details>
<summary>选择答案后查看结果</summary>

正确答案：D

答案解析：docker-compose.yml里所有敏感配置都通过secrets机制从./runtime-secrets/目录下的文件读取，如果没有先运行生成脚本，容器会因为找不到Secret文件而启动失败。

</details>

### 第 2 题

iot-simulator服务为什么平时不会随docker compose up自动启动？

- A. 因为它配置了profiles: [\"tools\"]，只有明确指定--profile tools时才会被启动
- B. 因为它依赖的镜像还没构建完成
- C. 因为它和gateway存在端口冲突
- D. docker compose本身不支持一次启动所有服务

<details>
<summary>选择答案后查看结果</summary>

正确答案：A

答案解析：Docker Compose的profiles机制允许把某些服务标记为可选，iot-simulator正是用profiles: [\"tools\"]标记为工具类服务，需要用docker compose --profile tools run --rm iot-simulator显式调用。

</details>

### 第 3 题

判断一次Trap发送是否\"成功\"的标准是什么？

- A. 只要UDP数据包发送出去没有报错就算成功
- B. 必须收到SNMP RESPONSE且errorStatus=noError，单纯的UDP写入成功不代表送达
- C. 只要Web页面显示了任意记录就算成功
- D. 只要容器没有崩溃就算成功

<details>
<summary>选择答案后查看结果</summary>

正确答案：B

答案解析：这是第4章讲过的Inform确认机制在实际操作中的体现：README特别强调，成功条件不是UDP写入，而是收到RESPONSE且errorStatus=noError，如果收到REPORT（比如unknown user、wrong digest、decrypt error）不能算作成功。

</details>

### 第 4 题

docker compose down -v这个命令会带来什么后果？

- A. 自动备份数据后再删除
- B. 仅仅停止容器，不影响任何数据
- C. 删除所有具名Volume，包括Oracle数据、USM状态和尚未处理完的重试队列数据，操作不可逆
- D. 只删除日志文件，不影响数据库

<details>
<summary>选择答案后查看结果</summary>

正确答案：C

答案解析：README特别提醒不要在生产数据或故障排查场景下执行这个命令，因为-v参数会连同具名卷一起删除，一旦执行，Oracle里保存的历史Trap数据和还未成功投递的重试队列内容都会永久丢失。

</details>

### 第 5 题

为什么gateway服务的启动要等待monitoring-app和trap-receiver都满足特定条件之后才开始？

- A. 这是为了节省系统资源
- B. Docker Compose强制要求所有服务按字母顺序启动
- C. 这只是随意的启动顺序，没有实际意义
- D. 确保网关开始接收流量时，后端处理服务已经就绪，避免请求被转发到还没准备好的目标

<details>
<summary>选择答案后查看结果</summary>

正确答案：D

答案解析：docker-compose.yml中gateway的depends_on对monitoring-app要求service_healthy(健康检查通过)，对trap-receiver要求service_started(已启动)，这样能最大程度保证请求进来时后端具备处理能力，这也是第18章高可用设计的延伸体现。

</details>
